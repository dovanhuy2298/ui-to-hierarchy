Second release of `ui-to-hierarchyMCP` — adds a one-line agent onboarding command and closes three v1.0 polish items on the output surfaces.

Available on npm as **[`ui-hierarchy-mcp`](https://www.npmjs.com/package/ui-hierarchy-mcp)** (v0.2.0).

## What's New

### `--init` — agent onboarding in one command

```bash
npx ui-hierarchy-mcp --init
```

Injects an MCP usage guide (when-to-call rules for the 4 tools, registration snippet, example invocations, `projectRoot` hint) into your agent's instruction file. Default target: `CLAUDE.md`. Opt into more via `--target`:

```bash
npx ui-hierarchy-mcp --init --target claude,codex,cursor,copilot
```

Writes to `CLAUDE.md` (claude), `AGENTS.md` (codex), `.cursor/rules/ui-hierarchy-mcp.mdc` (cursor, with proper YAML frontmatter), `.github/copilot-instructions.md` (copilot).

Properties:

- **Idempotent** — marker-delimited block (`<!-- ui-hierarchy-mcp:start version=X.Y --> ... :end -->`); re-runs are no-ops until the template upgrades
- **Atomic** — temp-file + `rename()` with `EXDEV` fallback; a crash mid-write cannot corrupt the target
- **CRLF/BOM-safe** — preserves the file's existing EOL convention and leading BOM as-is
- **Hand-edit aware** — SHA-256 fingerprint detects manual edits inside the block and skips them; `--force` overrides
- **CI-usable** — non-interactive by default; no prompts, no TTY checks; per-target summary to stderr; exit code `0`/`1`
- **`--dry-run`** — previews each target's would-be action (`would create` / `would update` / `would skip (no-op)` / `would skip (hand-edit detected)`) without writing
- **MCP server path unchanged** — running `npx ui-hierarchy-mcp` (no flag) still boots the stdio server exactly as in v0.1.0

### Polish

- **Markdown warnings surfaced** — when the analyzer emits envelope warnings, `format: "markdown"` now prefixes the output with `<!-- warning: {msg} -->` lines (previously dropped; JSON-only). Schema unchanged.
- **Markdown integration coverage** — integration suite now exercises `format: "markdown"` end-to-end against two fixtures (`phase-05/micro` and `kitchen-sink`), asserting tree glyphs, `@` file:line separator, and the Windows-backslash guard.
- **True line numbers on resolved components** — resolved local-kind component nodes report their actual `loc.start.line` instead of the v0.1.0 `line: 1` placeholder. Implemented by populating `ParseResult.declLines` in the existing single parse pass (zero extra cost; cache identity preserved).
