## Overview

v1.1 makes ui-hierarchy-mcp self-installing for AI coding agents and closes the three v1.0 polish items that surfaced after release. A new `npx ui-hierarchy-mcp --init` subcommand injects MCP usage guidance into agent instruction files (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules/ui-hierarchy-mcp.mdc`, `.github/copilot-instructions.md`) — idempotent, atomic, CRLF/BOM-safe, CI-usable. The markdown output surface now reaches parity with JSON (envelope warnings surfaced; integration suite exercises `format: "markdown"`); resolved component nodes report the true source declaration line instead of the v1.0 `line: 1` placeholder.

## Milestone Summary

**Key Decisions:**

- `--init` is non-interactive by default (no TTY checks, no prompts) — CI-safe and only `--force` overrides the hand-edit guard. Drove the marker-block + content-fingerprint design.
- Single template + per-target format wrapper (not per-target tailored content) — research showed 90%+ overlap across agents.
- Build-time `__INIT_MARKER_VERSION__` constant (mirrors `__TOOL_VERSION__`) — version baked at `tsup` build, not resolved at runtime. Trade-off: callers from `tsx`/`vitest` without a matching `define` would `ReferenceError`; acceptable because `runInit` is only invoked through `dist/cli.js`.
- `ParseResult.declLines` populated in the existing single parse pass — zero extra parse cost for POLISH-03; cache identity preserved.
- `renderMarkdown` warnings prefix uses HTML comments (`<!-- warning: {msg} -->`) — invisible in rendered markdown but recoverable; reaches parity with the JSON envelope without changing the schema.

**Issues Resolved:**

- v1.0 carry-forward closed: markdown envelope warnings (POLISH-01), markdown integration coverage (POLISH-02), resolved-component true line (POLISH-03).
- Agent onboarding gap: agents previously had to read README to learn the MCP tools; now `npx ui-hierarchy-mcp --init` writes the guide directly into their instruction files.
- Phase 7 / Phase 8 isolation verified: `src/init/*` imports nothing from `src/core/`, `src/ir/`, `src/renderers/`, or `src/mcp/` (zero overlap; init path cannot regress MCP path).

**Issues Deferred to v1.2:**

- F-01: live Claude Code transcript export (still reconstructed from stdio-equivalent capture).
- Two orphan exports in `src/mcp/errors.ts` (`notImplemented`, `invalidInput`) — Phase 2 stubs superseded by Phase 5.
- Auto-detect installed agents (scan filesystem for `.cursor/`, `.github/`, etc. and auto-populate `--target`).
- `--global` flag for `~/.claude/CLAUDE.md`.
- Hash-based upgrade detection across `version=X.Y` marker tag.

**Technical Debt Incurred:**

- `base.warnings ?? []` fallback redundant in all 4 tool handlers (cosmetic only — `buildEnvelope` always initializes `warnings: []`).
- `__INIT_MARKER_VERSION__` referenced in `src/init/index.ts` without `typeof` guard (unlike `__TOOL_VERSION__` in `src/mcp/server.ts`); safe today through `dist/cli.js`, would `ReferenceError` from direct `tsx`/`vitest` call.
