## v1 Requirements — All Satisfied

### MCP Shell

- [x] **MCP-01** — Ships as npm package with `bin` entry runnable via `npx ui-to-hierarch`; starts a stdio MCP server using `@modelcontextprotocol/sdk`'s `StdioServerTransport`. **Validated Phase 2.**
- [x] **MCP-02** — Every tool input defined via zod schema with `.describe()` on every field, precise types (enums, regex-validated identifiers, route-shape validators). **Validated Phase 2.**
- [x] **MCP-03** — Tool handlers return `{ content, isError: true }` on user-facing failures with actionable guidance — never propagate unhandled exceptions. **Validated Phase 2.**
- [x] **MCP-04** — stdout reserved exclusively for JSON-RPC frames; all diagnostics routed to stderr; `noConsole` lint on server paths + smoke test parsing every stdout line as JSON. **Validated Phase 2.**

### Query Tools

- [x] **TOOL-01** — `get_full_hierarchy(route, format?)` returns ordered layout chain + page subtree, markdown (default) or JSON. **Validated Phase 5.**
- [x] **TOOL-02** — `focus_on(component, scope)` with `scope ∈ {up, full, down}`. **Validated Phase 5.**
- [x] **TOOL-03** — `find_by_text(query)` returns matching nodes with file:line, fuzzy suggestions when no exact match (Levenshtein ≤2). **Validated Phase 5.**
- [x] **TOOL-04** — `find_by_style(class_or_prop)` returns nodes whose classes/style match, with file:line. **Validated Phase 5.**

### Parser Core

- [x] **PARSE-01** — Babel parse with full plugin set + `errorRecovery: true`; parse errors become `TreeNode { kind: "error" }`. **Validated Phase 3.**
- [x] **PARSE-02** — Barrel re-export resolution (recursive `ExportNamedDeclaration`/`ExportAllDeclaration`, cache, cycle guard). **Validated Phase 3.**
- [x] **PARSE-03** — tsconfig `paths` + `baseUrl` + `extends` chain via `get-tsconfig`. **Validated Phase 3.**
- [x] **PARSE-04** — HOC unwrap (`memo`, `forwardRef`, `observer`, `with*`, `*HOC`); `ClassDeclaration` extraction. **Validated Phase 3.**

### Next.js App Router

- [x] **NEXT-01** — Layout chain reconstruction is directory-based; includes `template.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`. **Validated Phase 4.**
- [x] **NEXT-02** — Route groups `(group)` contribute layouts but not URL segments; parallel `@slot` emitted as labeled slots; intercepting `(.)`, `(..)`, `(...)`, `(..)(..)` resolved; private `_folder` excluded. **Validated Phase 4.**
- [x] **NEXT-03** — Dynamic routes `[slug]`, `[...rest]`, `[[...opt]]` with resolved params in metadata. **Validated Phase 4.**
- [x] **NEXT-04** — `"use client"` / `"use server"` detected as first non-comment directive; every node carries `runtime`. **Validated Phase 4.**

### Output & Styling

- [x] **OUT-01** — Markdown tree (default) + JSON; every node carries `file` + `line`; forward-slash paths on Windows. **Validated Phase 1.**
- [x] **OUT-02** — Layout-only class filter by default; `fullClasses: true` reveals all. **Validated Phase 3.**
- [x] **OUT-03** — Style extractors: Tailwind (incl. `cn`/`clsx`/`cva`/`twMerge`), inline `style`, CSS Modules references, styled-components templates with `{?}` for interpolations. **Validated Phase 3.**
- [x] **OUT-04** — Conditional render branches preserved (`?:`, `&&`, `||`, `??`, `!`/`!!`); `.map` marked as `list` kind. **Validated Phase 3.**

### Architecture

- [x] **ARCH-01** — `FrameworkAdapter` interface with exactly 5 methods (`detect`, `discoverEntries`, `resolveModule`, `extractComponents`, `mapRouteToEntry`); `adapters/` is an island. **Validated Phase 3.**
- [x] **ARCH-02** — Parse on-demand — fresh `Analyzer` per tool call with per-call AST cache; no cross-call cache. **Validated Phase 5** (mutation test at `test/core/analyzer.test.ts:560–591` proves correctness).
- [x] **ARCH-03** — Project root resolution order: arg `projectRoot` > `UI_TO_HIERARCH_ROOT` env > `process.cwd()`; echoed in metadata. **Validated Phase 1.**
- [x] **ARCH-04** — Integration test suite with fixture Next.js projects (shadcn barrels, nested layouts, route groups, parallel slots, pnpm monorepo, Windows paths); MCP Inspector + Claude Code end-to-end. **Validated Phase 6** (20/20 integration green; 8/8 UAT PASS).

## v2 Requirements (deferred — carry forward to next milestone)

- Watch-mode / live indexing / cross-call AST cache
- HTTP/SSE transport
- Structural edit tools (`move_component`, `wrap_with`, `replace_props`)
- Pages Router support
- Additional framework adapters (React Native/Expo — port prototype; Vue; Svelte)
- CSS Modules full parsing (PostCSS) for layout-relevant declarations
- XML / Mermaid output renderers
- Route discovery tool (`get_route_map()`)
- Diff-between-routes / find-usages / summarize-component
- Render envelope warnings on markdown surface (currently dropped — see v1.0 deferred items)
- Markdown surface integration test coverage (currently JSON-only)
- True `line` for resolved component nodes (currently placeholder `line: 1`)

## Out of Scope (still valid for v2)

- **Vision / screenshot ingestion** — agents already have multimodal; MCP is code-only
- **Pages Router** — legacy; App Router-only buys deeper quality
- **Running or rendering the app** — static analysis only
- **Parsing `node_modules`** — libraries emitted as framework nodes with module name
- **`React.createElement` / `cloneElement` in v1** — JSX only; documented v1 gap
- **Dynamic className full resolution** — inherent limit of static analysis
