<!-- The critical Analyzer extension (RESEARCH.md Pitfall 1) -->
`collectChildrenSlotLines` in `src/core/Analyzer.ts` currently visits only `JSXExpressionContainer`. The extension adds a `JSXOpeningElement` visitor inside the SAME `traverse(ast, { ... })` call (same closure captures `adapter`, `bindings`, `lines`). The visitor inspects `path.node.name`: if it is a `JSXIdentifier`, look up the binding via `bindings.get(name)`, derive `importSource = binding?.source ?? ""`, and if `adapter.slotMarker(name, importSource)` returns true, add `path.node.loc?.start.line ?? 0` to the `lines` Set. Exact code shape is in 12-PATTERNS.md "src/core/Analyzer.ts (modify)" section.

<!-- Why the extension is safe for Next.js -->
`NextJsAdapter.slotMarker` returns `true` only when `name === "children"`. React syntax requires `{children}` (a `JSXExpressionContainer` wrapping a `JSXIdentifier`), NEVER `<children/>` (a JSXOpeningElement). The new visitor cannot fire on Next.js inputs, so the existing 388+ tests remain unaffected.

<!-- Warning emission contract -->
All warnings push into `ctx.warnings: string[]` (a property of `ParseContext`). Never `console.*`. The dual-root warning lives on `this.pendingWarnings: string[]` (instance field on ExpoRouterAdapter) and is FLUSHED into `ctx.warnings` at the start of `extractComponents`. The exact warning string format (locked):
- Dual-root: `"Both app/ and src/app/ exist at <absRoot>; using src/app/. Paths: <srcAppPath>, <appPath>"`.
- Namespace import: `"Namespace import '<localName>' from 'react-native' detected at <fwdFile>:<line> — members not classified as RN primitives"` (SPEC Req 10 exact text).
- Non-literal screen name: `"Non-literal name prop on <<navigatorName>.Screen> at <fwdFile>:<line> — screen not enumerated"`.

<!-- Tabs/Stack.Screen tree representation (D-01/D-02/D-03) -->
`<Tabs.Screen>` and `<Stack.Screen>` become child TreeNodes with `kind: "component"` (consistent with how every JSX element is rendered). `name` attribute → string attribute on the child node as-is. `options={...}` object → `JSON.stringify` compact serialization, omitting non-serializable values silently. The plain object is built from `ObjectExpression` properties: `StringLiteral`/`NumericLiteral`/`BooleanLiteral` values pass through; everything else is silently dropped. Per 12-RESEARCH.md "Open Questions" item 3, `Tabs.Screen` may already emerge as `kind: "component"` from the render-flow walker — if so, no special TreeNode synthesis is needed and the walker only contributes the `options` attribute summary + warning emission.
