<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `targetPath` argument → filesystem | Path is constructed in Plan 04 from cwd + target.relativePath; not user-controlled at runtime beyond enum selection |
| tmp file → final target | Tmp file lives in same directory as target; rename is the atomic commit |
| renderGuide cwd argument → output string | Caller-provided cwd is interpolated verbatim into the guide payload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-10 | Tampering | symlink at targetPath | mitigate | `rename(tmp, target)` follows the symlink and replaces the link's target. Acceptable because (a) target paths are fixed enum-derived names under cwd and (b) atomic rename guarantees no torn write. Documented in RESEARCH security domain. |
| T-07-11 | TOCTOU | concurrent process writes to same target | accept | Single-shot CLI invocation; concurrent `--init` runs against the same project are a misuse case. Atomic rename ensures the file is always one of the two consistent states. |
| T-07-12 | DoS | orphaned tmp files on crash | mitigate | Outer try/catch wraps the entire write sequence and calls `unlink(tmpPath).catch(() => {})` on any error path before rethrow (RESEARCH Pitfall 4) |
| T-07-13 | EoP | path traversal via `targetPath` containing `..` | accept | Plan 04 constructs targetPath via `join(cwd, target.relativePath)` from a closed enum. This plan's `writeAtomic` does not validate path; that responsibility lives in Plan 04. Documented as a layered invariant. |
| T-07-14 | Tampering | template literal injection via `cwd` | mitigate | `cwd` is interpolated into a markdown string only; it is not eval'd, not used as a path inside template.ts, and not user-controlled outside the user's own shell. Standard string interpolation with no shell or template engine. |
</threat_model>
