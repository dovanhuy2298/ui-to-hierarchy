src/init/index.ts (created here):
```typescript
export async function runInit(
  flags: InitFlags,
  options?: { cwd?: string }
): Promise<number>;
// Returns 0 iff every enabled target ended in {create | update | noop} (or `would *` under dryRun).
// Returns 1 if any target was skipped due to hand-edit (without --force) or any write threw.
```

Stderr action vocabulary (per D-12):
- Live mode: `create`, `update`, `noop`, `skip (hand-edit)`
- Dry-run: `would create`, `would update`, `would noop`, `would skip (hand-edit)`
Line format: `[init] <action> <relative-path>\n` written via `process.stderr.write`.

Cursor frontmatter contract (INIT-14):
```
---
description: ui-hierarchy-mcp usage guide — maps UI screenshots/descriptions to exact component file:line locations
alwaysApply: true
globs:
  - "**/*.tsx"
  - "**/*.jsx"
---

<!-- ui-hierarchy-mcp:start version=X.Y fingerprint=<64-hex> -->
...
<!-- ui-hierarchy-mcp:end -->
```

Decision logic per target:
1. Read existing file (catch ENOENT → "no file").
2. If no file: action = create. Render guide, compute fingerprint, wrap with markers, prepend cursor frontmatter if applicable, write with LF + no BOM.
3. If file exists, detect EOL + BOM. Scan for marker block.
4. If no marker: action = create (append after blank line); apply detected EOL + BOM.
5. If marker found:
   - If `version === __INIT_MARKER_VERSION__` AND `verifyFingerprint(body, fingerprint)`: action = noop (no write).
   - If fingerprint mismatch AND not `flags.force`: action = skip (hand-edit). Do not write.
   - Otherwise (version mismatch OR force): action = update. Render new block, replace in place, preserve EOL + BOM.

Stdlib: `readFile` from `node:fs/promises`, `join` from `node:path`. Reference the ambient global `__INIT_MARKER_VERSION__`.

    Export `async function runInit(flags: InitFlags, { cwd = process.cwd() }: { cwd?: string } = {}): Promise<number>`.

    **Fingerprint preimage contract (BLOCKER-driven invariant):** The fingerprint preimage is the `renderGuide(...)` output — call it `body` — with NO wrapping newlines. Plan 02's `BLOCK_PATTERN` is `<!-- ...:start version=(\S+) fingerprint=([0-9a-f]{64}) -->\n([\s\S]*?)\n<!-- ...:end -->`; the two literal `\n` outside the body capture consume the wrapping newlines added at block-assembly time. Therefore on re-scan, `scan.body === renderGuide(...)` byte-for-byte (after LF normalization), and `verifyFingerprint(scan.body, stored_fingerprint)` returns true on an unmodified file. **Do not deviate from this contract — it is the entire idempotency story.**

    Pipeline:
    1. Resolve enabled targets: filter `TARGETS` by `flags.targets.includes(t.id)`. Use `TARGETS` order (claude, codex, cursor, copilot) so output is deterministic.
    2. For each target, compute `absPath = join(cwd, target.relativePath)`. Initialize `existingBuf: Buffer | null` and `existingText: string | null` by trying `readFile(absPath)`. Catch the `ENOENT` error specifically and set both to null; rethrow any other error.
    3. Detect EOL + BOM from existing content. For a new file default to `eol = 'LF'`, `hasBom = false`.
    4. Render `body = renderGuide({cwd, version: __INIT_MARKER_VERSION__})`. **`body` is the fingerprint preimage — byte-identical to what `BLOCK_PATTERN` group 3 captures after a round-trip write+read.**
    5. Compute `fingerprint = computeFingerprint(body)`.
    6. Build the marker block: `markerBlock = `<!-- ui-hierarchy-mcp:start version=${__INIT_MARKER_VERSION__} fingerprint=${fingerprint} -->\n${body}\n<!-- ui-hierarchy-mcp:end -->` `. The two literal `\n` inside the assembled string are the SAME `\n` that `BLOCK_PATTERN` consumes outside its body capture group — this is what makes `body` the fingerprint preimage and ensures `computeFingerprint(scan.body) === stored_fingerprint` on the second run (regression test in Task 2).
    7. Decide action via the decision logic in the interfaces block. For the `update` and `skip` cases, scanBlock is called on the LF-normalized existing content (normalize via `existingText.replace(/\r\n/g, '\n')` for both `scanBlock` and `verifyFingerprint` inputs so the regex matches independent of EOL flavor).
    8. Produce the final output content per case:
       - `create` on missing file: if `target.hasFrontmatter`, prefix with the cursor frontmatter literal block + `\n\n` before the marker block. Apply `applyEolBom(content, eol, hasBom)`.
       - `create` on existing-no-marker: `appendBlock(existingText, markerBlock)`. Apply `applyEolBom`.
       - `update`: `replaceBlock(existingTextLfNormalized, markerBlock, scan)`. Apply `applyEolBom(content, eol, hasBom)`.
       - `noop`: skip the write entirely.
       - `skip (hand-edit)`: skip the write entirely; record the outcome.
    9. Choose writer: `flags.dryRun ? writeAtomicDryRun : writeAtomic`. Call only for `create | update`. For `noop` and `skip`, do nothing.
    10. Emit `process.stderr.write(\`[init] ${actionLabel} ${target.relativePath}\n\`)`. The actionLabel is `create | update | noop | skip (hand-edit)` in live mode, prefixed with `would ` in dry-run mode.
    11. Collect per-target outcomes. After the loop, return `0` iff every outcome is one of `create | update | noop` (or the `would *` equivalents); return `1` if any outcome is `skip (hand-edit)` or `would skip (hand-edit)` or if any per-target operation threw (catch around the per-target body; emit `[init] error <path>: <message>` and record a failure outcome).

    Define the cursor frontmatter as a `const CURSOR_FRONTMATTER` literal exactly:
    `---\ndescription: ui-hierarchy-mcp usage guide — maps UI screenshots/descriptions to exact component file:line locations\nalwaysApply: true\nglobs:\n  - "**/*.tsx"\n  - "**/*.jsx"\n---`

    For the `update` path on the cursor target, the existing-content slice approach via `scan.startIndex` and `scan.endIndex` (from markers.ts replaceBlock) preserves the frontmatter prefix byte-for-byte automatically — no special-case branching required (RESEARCH Pitfall 5).

    Do NOT call `process.exit` from inside runInit; Plan 05 / cli.ts handles that. Do NOT write to stdout. Do NOT read TTY state. Use the error coercion pattern `err instanceof Error ? err.message : String(err)` everywhere a `catch (err)` is needed.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-15 | Tampering | hand-edited marker block | mitigate | INIT-07: fingerprint mismatch → skip outcome → exit code 1; `--force` is the only override (D-13/INIT-13 — non-interactive override) |
| T-07-16 | Tampering | path traversal via target.relativePath | mitigate | Target paths are constants in `targets.ts`; user cannot inject a custom path. Only the four canonical paths under `cwd` are reachable. |
| T-07-17 | Information Disclosure | stdout contamination breaking MCP framing | mitigate | runInit uses `process.stderr.write` exclusively; integration test asserts `process.stdout.write` is called zero times (INIT-11) |
| T-07-18 | Tampering | TOCTOU between read and write | accept | Single-process CLI run; concurrent invocations on same project are misuse. Atomic rename in `writer.ts` guarantees no torn-write state regardless. |
| T-07-19 | Spoofing | cursor frontmatter corruption on re-run | mitigate | RESEARCH Pitfall 5: `replaceBlock` uses scanBlock's `startIndex`/`endIndex` to splice only the marker region, preserving all bytes before/after. | T-07-20 | Denial of Service | extremely large existing target file | accept | Agent instruction files are KB-scale; runInit reads the full file into memory once. No streaming needed for v1. |
| T-07-21 | Elevation of Privilege | symlink at target path replaces a sensitive file | accept | `rename` follows the link; if the user has placed an adversarial symlink at e.g. `CLAUDE.md` they already control their own project.
