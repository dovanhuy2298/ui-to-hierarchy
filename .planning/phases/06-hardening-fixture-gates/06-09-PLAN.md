<objective>
Close gap #2 from 06-DEBUG.md: the IR build pipeline never invokes the resolver to relocate a component callsite to its definition file. `walkRenderFlow.jsxElementToNode` records `file = <calling-file>` on every `kind:"jsx"` RenderNode (including `isComponent: true`); `Analyzer.renderNodeToTreeNode` copies that file straight into `kind:"component"` TreeNodes. The resolver itself is correct (tsconfig-paths + chaseBarrel both verified by Phase 3 unit tests) — the wiring is the bug. This plan adds the missing call: collect import bindings per entry from the cached AST, resolve each `isComponent` callsite, and override `file` (and `line`) when resolution lands on a local file.

Purpose: Satisfy SPEC R1 acceptance ("nodes whose file:line resolves to the leaf component files") and the analogous R3 monorepo cross-package acceptance ("imports of `@acme/ui` resolve to `packages/ui/src/*` files"). Without this fix, AI agents grounding screenshot edits would land on the wrong file (the consumer page, not the component source).
Output: `src/core/Analyzer.ts` modified to thread import-binding collection + resolveModule calls into the IR-build path. No schema change; no new resolver code.
</objective>

    ```ts
    // For a parsed module, return: localJsxName -> { source, importedName }
    // Covers:
    //   import { Foo } from "x"          → "Foo"      → { source: "x", importedName: "Foo" }
    //   import { Foo as Bar } from "x"   → "Bar"      → { source: "x", importedName: "Foo" }
    //   import Default from "x"          → "Default"  → { source: "x", importedName: "default" }
    //   import * as Ns from "x"          → not added (Ns.Foo is multi-hop; skip in v1, falls through to call-site file)
    function collectImportBindings(ast: t.File): Map<string, { source: string; importedName: string }> { ... }
    ```

    Use `@babel/traverse` (already imported at the top of Analyzer.ts) with the `ImportDeclaration` visitor. Skip `ImportNamespaceSpecifier` (the `* as Ns` form) — DEBUG explicitly carves this out as v1-acceptable to leave at call-site.

    **Step 2 — Hook the post-pass into `buildTreeForEntry`.** In the existing `buildTreeForEntry` (lines 508-572), after `bodyTree` is built and slot-injected (i.e., right after line 552 where `injectChildrenSlots` runs, and before the wrapping `kind:"component"` node is constructed at line 558), insert a resolver post-pass:

    ```ts
    // Resolve component callsites to their definition file (DEBUG #2 fix).
    // Only kind:"component" nodes whose `file` still equals the entry/call-site
    // are candidates; their `name` is the JSX tag, looked up in the import map.
    if (cachedParse && cachedParse.kind === "ok") {
      const bindings = collectImportBindings(cachedParse.ast);
      bodyTree = resolveComponentCallsites(bodyTree, bindings, absFile, this.adapter, this.ctx);
    }
    ```

    **Step 3 — `resolveComponentCallsites` (new module-private helper).** A recursive walker that, for each `kind:"component"` TreeNode:
    1. Look up `node.name` in `bindings`. If absent (locally declared, unresolved import, or namespace form), recurse into children unchanged.
    2. Call `adapter.resolveModule(ctx, fromFile, importSpec, exportName)` where:
       - `fromFile = absFile` (the entry being processed)
       - `importSpec = bindings.get(node.name).source`
       - `exportName = bindings.get(node.name).importedName`
    3. If the result is `{ ok: true, kind: "local", file, line? }`, return a new node with `file: toForwardSlash(file)` and `line: line ?? 1`. Recurse into children with the new context (their file may also need overrides, but they were already built off the original RenderNode tree — preserve their `file`s as-is; the per-entry pass handles only the top-level callsites it owns. Children of an `isComponent` node in render-flow are the JSX children passed AS PROPS, which still belong to the calling file's source — do NOT cascade the override into children).
    4. If the result is `{ ok: false }` or `{ ok: true, kind: "external" }`, leave the node's `file:line` alone AND append `this.ctx.warnings.push(`unresolved component '${node.name}' from '${importSpec}' at ${fwdFile}:${line}`)` only on `ok: false` (not on external — external is normal). Continue recursing.

    **Step 4 — Recurse into the other tree shapes.** The walker must handle every TreeNode kind whose subtree may contain `kind:"component"` nodes:
    - `kind:"component"`, `kind:"element"`, `kind:"fragment"` → walk `children`.
    - `kind:"branch"` → walk `thenBranch` and `elseBranch`.
    - `kind:"list"` → walk `item`.
    - `kind:"text"`, `kind:"slot"`, `kind:"error"`, `kind:"spread"` → return as-is.

    Reuse the cloning idioms from `replaceSlot` (Analyzer.ts:203-247) for shape consistency.

    - The wrapping outer `kind:"component"` node built at lines 558-566 of `buildTreeForEntry` retains its existing `file: toForwardSlash(def.file)` — that's already the correct entry-component file, not a callsite. Only INNER `kind:"component"` callsites (which `renderNodeToTreeNode` produced from `isComponent` RenderNodes) need overriding.

    - `astCache` is read-only here; do not mutate.

    - No change to public API of `Analyzer`.

    - Do NOT thread `bindings` through `renderNodeToTreeNode` — adds noise to a hot recursive function. The post-pass is cleaner and identical in effect because resolution is a leaf-level decision per node.
