# Phase 6 — UAT (Hardening & Fixture Gates)

This UAT verifies SPEC R6 — both Claude Code and MCP Inspector exercise all four MCP tools against the `nested-routes` fixture end-to-end.
Coverage = 2×4 grid per D-15. Findings recorded per D-13 schema; the `block` flag is governed by D-14 policy (falsifies-prior-phase rule).

## Runbook (Local Windows)

Execute in this order. Each step builds on the previous; do not skip.

1. `pnpm install`
2. `pnpm build` — produces `dist/cli.js`.
3. `pnpm test` — unit suite (existing).
4. `pnpm test:integration` — Phase 6 integration suite (R1–R5).
5. `pnpm test:smoke` — existing MCP smoke (MCP-01, MCP-04).
6. `pnpm perf` — generates/refreshes `06-PERF.md` (R7); commit if hardware unchanged.
7. **Stdout cleanliness probe** (defense in depth before connecting clients): On Windows: `node dist/cli.js < NUL` and confirm zero stdout output before EOF. POSIX equivalent: `node dist/cli.js < /dev/null`. Any non-empty stdout here will corrupt the JSON-RPC frame for both Inspector and Claude Code.
8. UAT — MCP Inspector: `npx @modelcontextprotocol/inspector node dist/cli.js`. In the Inspector UI, exercise each of the 4 tools against the `nested-routes` fixture. Use these arguments:
   - `get_full_hierarchy` → `{ "route": "/dashboard/123", "format": "json", "projectRoot": "<absolute path to test/fixtures/phase-06/nested-routes>" }`
   - `focus_on` → `{ "component": "DashboardDetail", "scope": "full", "projectRoot": "<...>" }`
   - `find_by_text` → `{ "query": "Sidebar slot", "projectRoot": "<...>" }`
   - `find_by_style` → `{ "class_or_prop": "grid-cols-3", "projectRoot": "<...>" }`

   Capture the session transcript to `uat-evidence/inspector-transcript.md` (or `.txt`). Optional: 1–2 PNG screenshots to `uat-evidence/inspector-*.png`.
9. UAT — Claude Code: configure your `~/.claude.json` (or per-project `.mcp.json`) with the entry:
   ```json
   {
     "mcpServers": {
       "ui-to-hierarch": { "command": "node", "args": ["<absolute path to dist/cli.js>"] }
     }
   }
   ```
   Restart Claude Code. Prompt the agent to invoke each of the 4 tools against `<absolute path to test/fixtures/phase-06/nested-routes>`. Capture the agent transcript (paste from Claude Code UI) to `uat-evidence/claude-code-transcript.md`. Optional 1–2 screenshots.
10. **Path redaction (D-12):** before committing any transcript / screenshot, replace any absolute path containing your home directory with the literal `<USER_HOME>`. (Example: `C:/Users/jane/...` → `<USER_HOME>/...`.) Use forward slashes in redacted paths.
11. Fill the PASS Grid below for each tool × client (8 checkboxes). For each FAIL or unexpected behavior, add a row to the Findings table with the appropriate Severity + Defer/Block flag.

## Findings (D-13 schema)

> **Severity:** `blocker` (cannot ship), `major` (degraded UX), `minor` (cosmetic / non-functional).
> **Defer/Block (D-14):** `block` ONLY when the finding falsifies a prior phase's verification. Concrete examples:
> - A tool returns `isError: true` on `nested-routes` where Phase 5 unit tests pass → `block` (falsifies Phase 5 R8 no-throw contract).
> - A `file` field contains a backslash where Phase 1 D-07 forward-slash discipline says it cannot → `block` (falsifies Phase 1 D-07).
> - Any other issue (UX papercut, slow-but-correct tool, deeper resolution gap not covered by prior phase acceptance) → `defer`.
